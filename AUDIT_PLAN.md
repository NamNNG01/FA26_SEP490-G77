# AI exam preparation platform: audit findings and verification plan

## Summary

**Two findings block release: a fresh PostgreSQL database cannot start the backend, and the exam API awards points for answers submitted after the deadline.** The audit is report only. The source tree is unchanged.

The baseline covers `Khai` at `eaac599`. The frontend production build passed, but TypeScript failed. The backend main code compiled, but the normal Maven test run stopped at test compilation. A separately compiled subset ran 181 tests: 179 passed and 2 failed. Local API and Chromium checks reproduced several additional defects.

## Confirmed findings

| Priority | Finding | Evidence |
|---|---|---|
| P0 | **Fresh database startup fails.** | Flyway applied 87 migrations through V88 on disposable PostgreSQL. Hibernate then refused to start because the question ID sequence increments by `1` while the entity expects `50`. Startup succeeded after applying the existing [test-only sequence adjustment](D:/Coding_Projects/Capstone_Project/FA26_SEP490-G77/BE/src/test/resources/db/postgres-test/afterMigrate.sql:5), which masks the mismatch in PostgreSQL tests. |
| P0 | **Timed exams accept late answers.** | A direct submit request with a fresh answer **two minutes after the deadline** returned HTTP 200 and awarded `10/10`. The [submit path](D:/Coding_Projects/Capstone_Project/FA26_SEP490-G77/BE/src/main/java/com/examprep/services/AttemptWriter.java:86) applies answers without the deadline check used by draft saves. |
| P1 | **A perfect score can exceed or fall short of the maximum.** | The [grading path](D:/Coding_Projects/Capstone_Project/FA26_SEP490-G77/BE/src/main/java/com/examprep/services/AttemptAutoSubmitter.java:114) rounds each answer before adding the scores. The production scoring functions returned `10.02/10` for six equally weighted correct answers and `9.99/10` for three. |
| P1 | **Rejected exam drafts are treated as saved.** | The [exam screen](D:/Coding_Projects/Capstone_Project/FA26_SEP490-G77/FE/src/features/student/pages/StudentTakeExamPage.tsx:262) clears rejected answers from its unsaved list. A browser test returned `INVALID_RESPONSE` from autosave; the page showed no rejection and did not retry the answer. |
| P1 | **Anonymous discussions expose the author, and posts can go to the wrong course.** | A second student received the anonymous author’s real user ID from the [discussion API](D:/Coding_Projects/Capstone_Project/FA26_SEP490-G77/BE/src/main/java/com/examprep/services/student/StudentDiscussionServiceImpl.java:154). A post submitted for course B was stored under course A, the student’s first active enrollment, and the submitted tag was ignored. |
| P1 | **Coding exam history exposes hidden test inputs while the attempt is open.** | [Submission history](D:/Coding_Projects/Capstone_Project/FA26_SEP490-G77/BE/src/main/java/com/examprep/services/StudentCodeExamServiceImpl.java:525) returns hidden inputs and allows another submission. The integration test explicitly exercises this behavior. A student can inspect those inputs and use them in a later submission. |
| P1 | **Admin controls report actions they never perform.** | In Chromium, [Admin Settings](D:/Coding_Projects/Capstone_Project/FA26_SEP490-G77/FE/src/features/admin/pages/SystemSettingsPage.tsx:121) reported success, sent no write request, and reverted on reload. An unknown user URL opened the first demo account. The manager dashboard and public practice-exam screens also use fixture data. |
| P1 | **Both normal verification commands have failures.** | Maven reports eight compilation errors in two discussion test classes that still use old APIs. TypeScript reports `TS2345` in [saved-question PDF export](D:/Coding_Projects/Capstone_Project/FA26_SEP490-G77/FE/src/services/studentProgress.service.ts:172); Vite’s build passes without catching it. |
| P2 | **The shared dialog has no accessible name.** | Chromium’s accessibility tree showed an unnamed dialog even though the [modal](D:/Coding_Projects/Capstone_Project/FA26_SEP490-G77/FE/src/components/ui/Modal.tsx:98) displays a heading. This is a shared component, so the issue can affect other confirmation flows. |

The backend subset also found a discussion test that expects a pending post in the public list and an AI retry test that returned HTTP 504. The discussion expectation conflicts with the implemented moderation rule; the AI timeout needs an isolated rerun before classifying it as a product defect. The frontend dependency scan flagged versions covered by [DOMPurify](https://github.com/cure53/DOMPurify/security/advisories/GHSA-6688-9rhm-gjv2) and [follow-redirects](https://github.com/follow-redirects/follow-redirects/security/advisories/GHSA-mrwp-f3q8-3g9p) advisories. An exploitable path in this application has not been established.

## Remaining verification

1. **Build and database:** Pin the commit and record tool versions. Run a clean frontend install, type check, and production build. Repeat fresh startup and a populated V87-to-V88 upgrade on disposable PostgreSQL 15 or newer with application migrations alone. Record the standard Maven failure separately from any independently runnable tests.
2. **Exam integrity and access:** Test guest, student, course manager, and admin routes with two users and two courses. Exercise saved and rejected drafts, retries, parallel tabs, deadline boundaries, submit-versus-expire races, frozen papers, full-score rounding, published-question archive rules, hidden coding cases, and contest rankings. Check both the API response and persisted state.
3. **End-to-end workflows:** Trace authentication and password recovery; course enrollment and access; question authoring, import, and publishing; practice, flashcards, and saved questions; discussions, contributions, and moderation; discounts, checkout, subscriptions, and rewards. Test Gemini, the code judge, storage, email, and PayOS through local stubs covering success, timeout, invalid responses, and retries. Check mobile layout, keyboard navigation, and error recovery using the [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md).
4. **Security and reliability:** Check ownership and visibility on every API route family, including cross-course reads and writes, answer-key disclosure, upload limits, webhook signatures and replay, quota accounting, and restart recovery for background jobs. Compare both frontend lockfiles, scan backend dependencies, and distinguish vulnerable packages from reachable application exploits.

## Audit completion criteria

Deliver one prioritized report with the affected role and workflow, exact reproduction, expected and actual behavior, source location, and recommended remediation for each defect. Mark each workflow **passed, failed, blocked, or unverified**, and distinguish reproduced defects from code findings and test issues. Use synthetic data and local services; live provider behavior remains unverified unless sandbox access is separately authorized.
